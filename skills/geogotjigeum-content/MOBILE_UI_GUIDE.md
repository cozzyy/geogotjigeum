# 그곳지금 콘텐츠 모바일 UI 가이드 v1.0

신규 작품 콘텐츠는 모바일을 먼저 설계한다. 데스크톱 페이지를 단순 축소하는 방식은 기본 접근으로 사용하지 않는다.

## 1. 기준 화면
최소 다음 폭에서 검토한다.
- 360px
- 390px
- 430px

가능하면 실제 모바일 브라우저 또는 반응형 미리보기로 확인한다.

## 2. 첫 화면
첫 1~2스크린에서 사용자가 아래를 이해할 수 있어야 한다.
- 어떤 작품인가
- 왜 이 페이지를 봐야 하는가
- 가장 중요한 발견/장소/이야기가 무엇인가
- 다음에 무엇을 누르면 되는가

제목, 비주얼, 핵심 카피, CTA가 서로 경쟁하지 않도록 한다.

## 3. 모바일 내비게이션
콘텐츠가 길기 때문에 다음 중 작품에 적합한 방식을 검토한다.
- 스크롤 가능한 섹션 탭
- 접히는 목차
- 하단 주요 CTA
- 섹션 점프

메뉴가 본문을 과도하게 가리지 않도록 한다.

## 4. 등장인물 100명 이상
한 번에 100명을 길게 나열하지 않는다.

권장 탐색:
- 주연/조연/관계집단 탭
- 이름 검색
- 관계 그룹 필터
- 카드 접기/펼치기
- 주요 인물 우선 노출 후 전체보기

카드에는 모바일에서 필요한 정보만 우선 노출한다.

## 5. 장소 100개 이상
권장 탐색:
- 지도/목록 전환
- 지역 필터
- FILMING/STORY/SET/HISTORY/RECOMMENDATION 필터
- 검색
- 대표 장소 우선 노출
- 현재 위치/가까운 순 기능은 구현 가능성 검토

지도 위 마커가 과밀해지면 클러스터링 또는 필터를 고려한다.

## 6. 카드와 텍스트
- 한 카드에 너무 많은 정보를 넣지 않는다.
- 긴 주소/지명은 줄바꿈 또는 축약 후 상세보기로 보완한다.
- 본문은 짧은 문단과 명확한 소제목을 사용한다.
- 지나친 가로 스크롤은 피한다.
- 해시태그는 여러 줄로 자연스럽게 감기도록 한다.

## 7. 이미지
- 모바일에서 이미지가 본문 흐름을 압도하지 않게 한다.
- 적절한 aspect ratio와 lazy loading을 사용한다.
- 텍스트가 이미지 위에 올라갈 경우 대비와 가독성을 확인한다.
- 출처/캡션은 읽을 수 있는 크기로 유지한다.

## 8. 지도
- 지도와 본문을 동시에 좁은 화면에 억지로 나누지 않는다.
- `지도 보기 / 목록 보기` 전환을 우선 검토한다.
- 장소 상세에서 뒤로 돌아왔을 때 사용자의 탐색 위치를 가능한 유지한다.
- 지도 CTA는 손가락으로 누르기 쉬워야 한다.

## 9. 퀴즈
- 질문은 한 화면에서 핵심을 파악할 수 있게 작성한다.
- 4개 선택지는 세로 배치를 기본으로 한다.
- 선택지 간 간격을 충분히 둔다.
- 정답/오답 피드백 뒤 `이 장소 보기`와 `다음 문제` 우선순위를 명확히 한다.
- 진행상태 `7 / 20`과 현재 정답 수는 작지만 잘 보이게 한다.
- 장소를 새 탭/오버레이로 볼 때 퀴즈 상태가 사라지지 않도록 한다.

## 10. 터치와 접근성
- 주요 터치 타깃은 최소 약 44px 수준을 목표로 한다.
- 아이콘만으로 의미가 불명확하면 라벨을 추가한다.
- hover만으로 정보를 제공하지 않는다.
- 색상만으로 상태를 구분하지 않는다.

## 11. 성능
특히 신규 콘텐츠는 이미지와 데이터가 많으므로 다음을 확인한다.
- 이미지 최적화
- lazy loading
- 불필요한 대형 스크립트 최소화
- CLS 최소화
- 초기 화면에 필요하지 않은 100명/100장소 전체 데이터를 한 번에 무겁게 렌더링하지 않는 방식 검토

## 12. 완료 전 모바일 QA
Claude/개발자는 가능하면 다음을 실제 확인한다.
- 360px: 레이아웃 파손/가로 스크롤
- 390px: 일반 스마트폰 기준 탐색성
- 430px: 큰 스마트폰 기준 여백/카드 폭
- 첫 화면 CTA
- 인물 검색/필터
- 장소 검색/필터
- 지도 이동
- Quiz 메뉴 진입
- 20문제 퀴즈 선택/피드백/완료
- 언어 전환

모바일 QA 결과는 PR에 간단히 기록한다.
