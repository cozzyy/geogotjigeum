# 그곳지금 콘텐츠 제작 스킬 v1.1

## 1. 언제 사용하나
다음 작업에서는 이 스킬을 반드시 적용한다.
- 신규 영화/드라마/예능/애니메이션/OTT 작품 등록
- 기존 작품 콘텐츠 대규모 확장
- 작품별 등장인물/장소/해시태그 데이터 구축
- 후킹 페이지, 촬영지, 여행코스, 숨은 이야기, 퀴즈의 통합 기획
- 신규 콘텐츠 개발을 Claude에게 넘기기 위한 기획안 작성

단순 오탈자 수정, 짧은 카피 1~2줄 수정에는 강제하지 않는다.

## 2. 핵심 철학
그곳지금의 작품 콘텐츠는 단순한 줄거리 요약이나 촬영지 목록이 아니다.

**작품 → 인물 → 장면 → 실제 장소 → 숨은 이야기 → 여행 → 지도 → 퀴즈 → 검색**이 서로 연결되는 데이터형 콘텐츠를 만든다.

기본 원칙:
- 양은 충분히 크게 만든다.
- 숫자를 채우기 위해 사실을 만들어내지 않는다.
- 작품마다 다른 경험을 만든다.
- 모바일 화면을 1순위로 설계한다.
- 경쟁 콘텐츠를 충분히 조사하되 복제하지 않는다.
- 사용자가 읽고 끝나는 것이 아니라 지도·퀴즈·장소 탐색으로 이동하도록 설계한다.

## 3. 최소 목표 규모
신규 주요 작품은 아래 규모를 기본 목표로 한다.

### 등장인물
- 목표: **100명 이상**
- 주연, 조연, 단역, 가족, 조직, 관계 인물, 공식 크레딧 인물을 폭넓게 조사한다.
- 동일 인물의 아역/성인역 등은 필요 시 별도 배역 노드로 관리하되 동일 인물임을 명확히 표시한다.
- 이름 없는 기능 배역은 공식 크레딧 또는 신뢰 가능한 근거가 있을 때만 포함한다.

### 장소
- 목표: **100개 이상**
- 단순 촬영지만 100개를 억지로 찾지 않는다.
- 아래 유형을 구분하여 확장한다.
  - `FILMING`: 실제 촬영 확인 장소
  - `STORY`: 작품 속 이야기 배경
  - `SET`: 세트/재현 공간
  - `HISTORY`: 작품 이해에 중요한 역사·문화 연계 장소
  - `RECOMMENDATION`: 작품 테마와 연결되는 여행 추천 장소
- 실제 촬영 여부가 불확실한 곳은 `FILMING`으로 표시하지 않는다.

### 해시태그/검색 키워드
- 작품명, 원제, 배우, 등장인물, 지역, 장소, 장면, 시대, 감정, 장르, 여행, 촬영지, 밈, 글로벌 검색어를 폭넓게 구축한다.
- 단순 반복어를 제외하고 충분히 풍부한 키워드 풀을 만든다.
- KR / EN / JP / ZH 검색 확장을 고려한다.

### 본문 분량
- 작품 소개 몇 문단으로 끝내지 않는다.
- 줄거리, 인물관계, 대표 장면, 장소, 제작 비하인드, 지역 이야기, 여행 포인트가 각각 독립적으로 읽힐 정도의 깊이를 확보한다.

## 4. 숫자 하한선과 정확성 충돌 시 처리
`100명 이상`, `100개 이상`은 목표 하한선이지 허위 데이터 생성 명령이 아니다.

검증 가능한 데이터가 목표보다 적으면:
1. 추가 소스를 더 조사한다.
2. 관계 인물/역사·테마 장소 등 정당한 확장 범위를 검토한다.
3. 그래도 부족하면 검증 가능한 최대치까지만 작성한다.
4. 기획안에 `목표 미달`, 실제 확보 수, 부족 사유를 명확히 기록한다.

금지:
- 존재하지 않는 인물 생성
- 확인되지 않은 장소를 촬영지로 단정
- 같은 장소/인물을 이름만 바꿔 중복 카운트
- SEO 숫자를 늘리기 위한 무의미한 태그 반복

## 5. 작품별 필수 콘텐츠 구성
가능하면 아래 요소를 모두 설계한다. 순서는 작품에 맞게 바꿀 수 있으며, 매 작품 같은 순서로 반복하지 않는다.

- 후킹 영역
- 작품 기본정보
- 스포일러 안전 작품 소개
- 충분한 줄거리/세계관
- 인물 관계 및 등장인물 데이터
- 대표 장면
- 대표 장소 TOP 5~10
- 전체 장소 데이터
- 실제 촬영지 vs 극중 배경 구분
- 지도 탐색
- 지역별/테마별 여행코스
- 주변 연계 장소
- 제작 비하인드
- 잘 알려지지 않은 숨은 이야기
- 작품마다 다른 의외성/발견 포인트
- **20문제 퀴즈 메뉴**
- 관련 작품/배우/지역 연결
- SEO 제목/설명/롱테일 키워드
- 다국어 확장 기준
- 출처와 검증일

## 6. 후킹과 서술 — 반복 공식 금지
후킹은 필요하지만 **반전 문장 하나를 매번 핵심 공식으로 사용하지 않는다.**

금지되는 반복 습관 예:
- `드라마 속 OOO, 사실 OOO였다`
- `알고 보니 OOO`
- `한 곳인 줄 알았는데 여러 곳이었다`
- 매 작품마다 첫 문장을 반전형으로 시작
- 모든 작품에서 같은 TOP5 → 숨은 이야기 → 지도 순서를 기계적으로 반복

신규 작품 기획 전:
1. 기존 그곳지금 최근 콘텐츠 3개 이상을 확인한다.
2. 제목, 첫 문장, 후킹 방식, 페이지 순서가 반복되는지 본다.
3. 해당 작품에 맞는 **서로 다른 콘셉트 3개 이상**을 먼저 만든다.
4. 경쟁조사 결과와 작품 특성을 보고 가장 차별적인 안을 선택한다.

가능한 각도의 예시는 참고일 뿐 고정 템플릿이 아니다.
- 장소 미스터리/퍼즐
- 인물 감정선과 장소 연결
- 시간순 여행 지도
- 하루 동선
- 제작진의 로케이션 선택 추적
- 실제 역사와 극중 세계 비교
- 한 장면을 여러 장소로 해체
- 배우별 장소 지도
- 계절/색감/음악과 장소 연결
- 현지 주민 관점

**같은 각도를 연속 작품에 습관적으로 재사용하지 않는다.**

## 7. 일반 사용자 톤
기본 독자: 20~30대.

원칙:
- 친구가 얘기해주는 듯한 자연스러운 말투
- 짧은 문장과 리듬
- 개인적 반응이나 함께 발견하는 느낌 허용
- 과도한 정보 나열 지양
- AI가 쓴 듯 지나치게 매끈한 문장 지양
- 가르치거나 훈계하는 말투 금지
- 작품마다 말의 리듬과 시작 방식도 조금씩 달리한다.

단, 데이터 필드·관리문서는 정확하고 구조적인 문체를 사용한다.

## 8. 모바일 퍼스트 설계 — 필수
신규 콘텐츠는 데스크톱 축소판이 아니라 **모바일 화면을 먼저 설계**한다.

기획 단계부터 `MOBILE_UI_GUIDE.md`를 적용한다.

필수 검토:
- 360 / 390 / 430px 폭에서 첫 화면이 무너지지 않는가
- 핵심 제목과 CTA가 첫 1~2스크린 안에 보이는가
- 카드·인물·장소 목록이 한 손 스크롤에 적합한가
- 버튼/탭 터치 영역이 충분한가
- 긴 해시태그·인물명·지명이 넘치지 않는가
- 지도와 텍스트의 전환이 모바일에서 단순한가
- 이미지 비율과 자막이 과도하게 화면을 차지하지 않는가
- 퀴즈 선택지와 다음 버튼이 엄지손가락으로 편한가
- 고정 메뉴/하단 CTA가 콘텐츠를 가리지 않는가
- 긴 100명/100장소 데이터는 검색·필터·접기·탭 등으로 탐색 가능한가
- 모바일에서 페이지가 지나치게 길어질 경우 섹션 내비게이션을 제공하는가
- 로딩, 이미지 용량, CLS 등 체감 성능을 고려하는가

모바일 설계가 불충분하면 콘텐츠 기획을 Done으로 보지 않는다.

## 9. 경쟁 사이트·유튜브·커뮤니티 분석 — 필수
신규 콘텐츠는 조사 없이 내부 아이디어만으로 기획하지 않는다.

반드시 `RESEARCH_PLAYBOOK.md`를 적용한다.

가능하면 다음을 조사한다.
- 공식 플랫폼/제작사/방송사
- 국내외 촬영지·팬·여행 관련 경쟁 사이트 3개 이상
- 관광/지역 공식 사이트 2개 이상
- 조회수/영향력이 높은 관련 YouTube 영상 3개 이상
- 메이킹/인터뷰/비하인드 자료
- 블로그·커뮤니티·댓글에서 반복되는 질문과 오해

조사 후 반드시 정리:
- 다른 곳이 이미 잘하고 있는 것
- 대부분 반복하는 흔한 정보
- 다른 곳에서 빠져 있는 것
- 시청자/독자가 실제로 궁금해하는 것
- 그곳지금이 추가할 수 있는 새로운 관점 3개 이상

경쟁 콘텐츠의 문장·페이지 구성을 복제하지 않는다. 분석 결과를 조합해 더 깊고 새로운 콘텐츠로 재설계한다.

## 10. 숨은 이야기 기준
각 주요 작품에는 강한 숨은 이야기/발견 포인트를 확보한다. 단, 반드시 `반전 한 줄` 형태일 필요는 없다.

후보:
- 촬영 장소 조합/합성
- 장소의 실제 역사와 작품의 연결
- 배우/제작진 촬영 비하인드
- 세트와 실제 장소 차이
- 삭제 장면/로케이션 변경/촬영 난관
- 공개 후 현지 변화
- 팬들이 자주 오해하는 장소/설정
- 장면을 다시 보게 만드는 제작 선택

흔한 위키 수준 정보보다 한 단계 깊은 자료를 찾는다.

## 11. 퀴즈 20문제 — 신규 작품 기본 메뉴
앞으로 신규 주요 작품에는 **독립적인 퀴즈 메뉴와 20문제**를 기본 구성으로 만든다.

기준 문서:
- `docs/product/quiz-expansion-plan-v1.1.md`
- 기존 `폭싹 속았수다` 퀴즈 메뉴/구현이 코드나 운영 사이트에 존재하면 우선 UI/동작 참고

기본 구성:
- 총 20문제
- 4지선다
- 작품 기억/인물·사건: 약 5문제
- 장소·촬영지: 약 8문제
- 숨은 이야기·비하인드: 약 4문제
- 팬용 세부 문제: 약 3문제
- 20문제 중 8~10문제는 장소 페이지/지도와 연결 권장
- 선택 즉시 정답/오답 + 짧고 유용한 해설
- 완료 화면: 점수 + 작품별 결과 문구 + 장소/다른 작품 CTA
- 로그인/랭킹은 기본 요구가 아님
- 작품별 `/works/{slug}/quiz/`와 같은 검색 가능한 독립 URL을 권장
- 퀴즈 질문/정답/해설은 SEO와 내부링크에 활용 가능하도록 구조화

문제 제작 원칙:
- 단순 줄거리 암기만 20개 만들지 않는다.
- 그곳지금의 차별점인 장소·여행·비하인드를 충분히 포함한다.
- 정답이 객관적으로 검증 가능해야 한다.
- 한 문제에 정답이 둘 이상 될 가능성이 있으면 다시 작성한다.
- 모바일에서 한 화면에 질문과 4개 선택지가 자연스럽게 읽히도록 길이를 조절한다.

- 촬영지
- 장면/대사/사건

- 중국어 SEO

## 16. 여행 확장
각 작품에서 검토:
- 반나절 코스
- 1일 코스
- 지역별 코스
- 대중교통 중심 코스
- 도보 클러스터
- 주변 맛집/관광지는 별도 검증 후 연결
- 같은 지역 다른 작품 촬영지 연결
- 현재 위치 기반 주변 촬영지 확장 가능성

## 17. 다국어
기본 지원 언어는 `PROJECT_STATE.md`의 최신 정책을 따른다.

원칙:
- 단순 직역 금지
- 작품명·인명·지명은 해당 언어권 공식 표기 우선
- 해당 언어 콘텐츠가 실제로 준비되지 않은 경우 다른 언어 페이지로 조용히 보내지 않는다.
- 다국어 작업 전 language availability 규칙을 확인한다.

## 18. 신규 콘텐츠 기획 결과물 최소 항목
ChatGPT가 Claude에게 넘길 기획안에는 최소 다음을 포함한다.
- 작품 선정 이유와 최신성/인기도 근거
- 경쟁 사이트/YouTube 분석 요약
- 흔한 정보 vs 콘텐츠 공백
- 서로 다른 콘셉트 후보 3개 이상과 최종 선택 이유
- 모바일 첫 화면/내비게이션/주요 섹션 설계
- 작품 기본정보
- 예상 등장인물 데이터 규모
- 예상 장소 데이터 규모
- 주요 장소 후보
- 숨은 이야기/발견 포인트
- 페이지 구조
- 20문제 퀴즈 설계
- 해시태그/SEO 전략
- 여행 확장
- 다국어 전략
- 필요한 데이터/개발 작업
- 완료 기준
- 검증이 더 필요한 항목

## 19. Claude 개발 인수인계
기획이 개발로 이어지는 경우 반드시 `docs/CHATGPT_CLAUDE_HANDOFF.md`를 함께 따른다.

ChatGPT는:
- 기획안을 `docs/content/`에 저장
- Handoff Issue 생성
- 개발 승인 상태를 임의로 승인하지 않음

Claude는:
- 이 스킬, `MOBILE_UI_GUIDE.md`, `RESEARCH_PLAYBOOK.md`, 기획안을 읽은 뒤 기술 검토
- 기존 폭싹 퀴즈 구현이 있으면 재사용 가능한 컴포넌트/패턴을 우선 확인
- `READY FOR APPROVAL / NEEDS DECISION / BLOCKED` 중 하나로 보고
- 사용자 승인 전 코드 구현 금지

## 20. 지속 개선 — 스킬 자체를 살아있는 기준으로 관리
콘텐츠 개발 중 **다른 작품에도 반복 적용될 가능성이 높은 규칙·실수·개선점**을 발견하면 이 스킬을 업데이트한다.

에이전트는 다음 경우 자발적으로 스킬 업데이트를 검토한다.
- 사용자가 같은 요구를 두 번 이상 반복함
- 여러 작품에서 같은 QA 문제가 발생함
- 새로운 공통 UI/데이터/SEO/퀴즈 규칙이 생김
- 경쟁 분석에서 장기적으로 유효한 제작 원칙을 발견함
- 기존 규칙 때문에 반복적으로 콘텐츠가 획일화됨

사용자 재승인 없이 추가 가능한 것:
- 기존 방향을 강화하는 체크리스트
- 새로운 반복 QA 항목
- 모바일/SEO/조사/퀴즈의 세부 기준
- 명백한 중복·모호성 정리

사용자에게 먼저 알려야 하는 큰 변경:
- 등장인물/장소 목표 수 축소
- 지원 언어 정책 변경
- 핵심 데이터 스키마 대규모 변경
- 새로운 유료 서비스 도입을 기본값으로 지정
- 승인 Gate나 프로젝트 운영 원칙 변경

업데이트 시:
1. `SKILL.md` 또는 관련 보조 파일 수정
2. `QUALITY_CHECKLIST.md`와 `CONTENT_PLAN_TEMPLATE.md` 영향 확인
3. `CHANGELOG.md`에 이유와 변경내용 기록
4. 중요한 변경은 PR 또는 Git 기록으로 남김

## 21. 품질 게이트
콘텐츠를 완료로 보기 전에 `QUALITY_CHECKLIST.md`를 사용해 점검한다.

특히 다음 중 하나라도 문제가 있으면 Done 처리하지 않는다.
- 가짜/추정 인물을 사실처럼 작성
- 촬영지 근거 미확인
- 장소 유형 미구분
- 경쟁 콘텐츠 조사 없이 상투적 기획
- 최근 콘텐츠와 동일한 후킹/구조 반복
- 모바일 화면 설계 부재
- 퀴즈 20문제/Quiz 메뉴 부재(신규 주요 작품 기준)
- 검색/해시태그 빈약
- 여행 연결 부재
- 출처/검증일 부재
- 기획안과 구현 결과가 크게 불일치
