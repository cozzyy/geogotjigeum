# 그곳지금 구조조정안 v1 — Verified Minimalism

Status: **PLANNED / USER REVIEW**

## 0. 한 줄 방향

그곳지금은 `많이 알려주는 콘텐츠 DB`가 아니라 **좋아한 작품의 실제 장소를, 검증된 핵심 정보만으로 빠르게 이해하고 가볼 수 있게 하는 서비스**로 재정렬한다.

핵심 원칙:

> **확실한 것만, 필요한 만큼만 보여준다.**

이번 구조조정의 목적은 새 기능 추가가 아니다. 이미 쌓인 기능·정보·URL을 모두 유지하려는 집착을 버리고, 사용자에게 보이는 1차 경험을 단순하게 만들어 신뢰도·가독성·관리 가능성을 높이는 것이다.

---

# 1. 현재 문제 정의

## 1.1 정보량이 많을수록 검증 비용이 폭증한다

작품 한 편에 장소 20~30개, 등장인물, 연대기, 관계도, 문화정보, 퀴즈, 지역정보, 지도, 여행코스 등을 한꺼번에 보여주면 각 주장마다 사실검증이 필요하다.

결과적으로 사용자에게 큰 가치가 없는 부가정보까지 데이터에 포함되고, 작은 지역명/관계분류 오류 하나가 전체 서비스 신뢰를 깎는다.

`강원 연천` 같은 오류는 단순 QA 부족의 문제가 아니라 **필요하지 않은 정보까지 노출하는 구조 자체의 문제**로 본다.

## 1.2 콘텐츠 화자가 실제 운영자 경험처럼 보인다

현재 일부 글은 `내가 찾아봤는데`, `생각보다 재미있다` 같은 개인 블로그 화법을 사용한다. 실제 운영자의 직접 체험·의견이 아닌 경우 이 화법은 쓰지 않는다.

앞으로 기본 톤은:
- 친구에게 설명하듯 자연스럽되
- 개인 체험을 가장하지 않고
- `편집된 콘텐츠 가이드`의 목소리를 사용한다.

## 1.3 사용자가 이해해야 할 서비스 구조가 너무 많다

현재 앱에는 장소/작품/인물/여행 탭, 지역 탐색, 주변 탐색, 검색, 작품 상세, Place, Map, Quiz, Guide, Scene, 인물 관계 등 여러 진입점이 존재한다.

Work Detail 자체도 `TOP5 → 등장인물 → 전체 장소 목록`을 연속으로 펼쳐 보여주는 구조다. 현재 generator 역시 이 구조를 그대로 렌더링한다.

사용자가 실제로 묻는 질문은 훨씬 단순하다.

1. 이 장면 어디서 찍었지?
2. 여기 진짜 촬영지 맞아?
3. 지금 가볼 수 있나?
4. 가면 볼 가치가 있나?

1차 UX는 이 4개 질문에 집중한다.

# 2. 새 제품 원칙

## 2.1 Claim Budget

작품 페이지가 주장할 수 있는 핵심 사실 수를 의도적으로 제한한다.

### Work Detail 기본 상한
- 대표 Scene: 최대 3개
- 대표 실제 장소: 기본 3~5개
- 숨은 사실/반전: 최대 3개
- 본문에서 직접 강조하는 핵심 factual claim: 최소 필요 범위

장소가 28개 있다고 해서 28개를 1차 화면에 모두 설명하지 않는다.

## 2.2 Evidence First

핵심 장소는 아래 관계를 명확히 분리한다.

- `FILMED` — 실제 촬영 확인
- `STORY_SETTING` — 작품/원작 속 배경
- `EXPERIENCE` — 공식 체험/전시
- `INSPIRATION` — 모티프·영감
- `UNVERIFIED` — 확인 부족

1차 추천 영역에는 원칙적으로 **검증 가능한 FILMED/EXPERIENCE와 명확히 구분된 STORY_SETTING만** 사용한다.

`UNVERIFIED`는 핵심 카드에 넣지 않는다.

## 2.3 Facts over Decoration

사용자가 행동하는 데 필요하지 않은 정보는 삭제 또는 2차 영역으로 내린다.

정보를 추가하기 전에 항상 묻는다.

> 이 정보가 없으면 사용자가 작품 장소를 이해하거나 방문하는 데 실제로 불편한가?

아니면 1차 화면에서 제외한다.

## 2.4 One Fact, One Source-of-Truth

관계분류·장소명·지역·설명은 여러 template에서 별도로 추정하지 않는다.

Work / Place / Map / Guide는 동일한 canonical location record를 읽는다.

# 3. 정보구조(IA) 재편

## 3.1 최상위 Navigation

### v1 목표

```text
로고 | 작품 | 지도 | 장소 | 검색 | 언어
```

모바일:

```text
작품 | 지도 | 검색
```

`저장`은 Phase G 구현 후 작은 utility action으로 추가할 수 있으나, 구조조정 전에는 새 핵심 Nav로 추가하지 않는다.

### Primary nav에서 제외
- 인물
- 여행
- 퀴즈
- 지역
- Guide
- 관계도
- 연대기

기능 삭제와 nav 삭제는 다르다. 필요한 기능은 2차 링크/관련 콘텐츠로 남길 수 있다.

## 3.2 Homepage

홈페이지 목표는 **작품을 찾고 바로 장소 경험으로 들어가는 것**이다.

### 남김
1. 한 줄 서비스 설명
2. 작품 검색
3. 대표/최근/인기 작품 카드
4. 지도 진입 CTA

### 축소/2차화
- 지역별 여행
- 내 주변 여행
- 여행지 찾기
- 오늘의 장소
- 사용법 modal
- 여러 개의 동급 CTA

한 화면에서 primary action은 최대 2개:

```text
작품 찾기
지도에서 보기
```

# 4. Work Detail 새 구조

## 현재 문제

현재 Work generator는 대표 장소 TOP5 뒤에 등장인물, 전체 장소 목록을 연속으로 노출한다. 정보량이 커질수록 페이지가 데이터 덤프처럼 보이고 오류 표면적도 커진다.

## 새 기본 구조

### A. Hero
- 작품명
- 짧은 소개 3~5문장
- 작품을 좋아한 사람이 왜 이 장소들을 궁금해할지 1문장
- CTA: `지도에서 보기`

### B. 장면으로 다시 보기 — 최대 3개

Scene package가 있고 검증된 작품만 노출.

각 카드:
- 일러스트/검증된 이미지
- 장면 맥락 1~2문장
- 관계 badge
- 연결 장소

### C. 꼭 볼 장소 — 3~5개

기존 TOP5 개념을 `대표 촬영지 TOP5` 같은 랭킹보다 **편집 추천**으로 바꾼다.

카드당 정보:
- 장소명
- 관계: 실제 촬영지/작품 배경/공식 체험
- 어떤 장면인지
- `왜 가볼 만한지` 1~2문장
- 지도 CTA

불필요한 행정구역·세부 지명은 사용자 가치가 있을 때만 쓴다.

### D. 의외의 사실 — 최대 3개

잘 알려지지 않은 촬영 비하인드나 location twist만 선별한다.

검증이 약하면 넣지 않는다.

### E. 지도

핵심 3~5곳을 바로 지도에서 확인.

### F. 더 많은 장소 — Secondary / Collapsed

전체 장소 DB를 반드시 삭제할 필요는 없다.

단:
- 기본 접힘
- 검증된 장소만
- compact list
- 긴 설명 반복 금지

검색 유입이나 실제 사용자 수요가 없는 경우 페이지 본문에서 아예 제외 가능하다.

### G. 출처와 검증

페이지 하단에 짧게:
- 어떤 종류의 자료를 사용했는지
- 마지막 검토일
- 일부 장소의 관계가 왜 촬영지/배경으로 분류됐는지

모든 문장마다 각주를 붙이는 방향이 아니라 **보여주는 주장 자체를 줄이는 방식**으로 관리한다.

# 5. Work Detail에서 제거/2차화할 것

## 기본 화면에서 제거
- 등장인물 7~8명 리스트
- 배우 프로필 링크 묶음
- 전체 장소 20~30개 장문 카드
- 작품 연대기
- 인물 관계도
- 문화정보 cross-link 다발
- 퀴즈를 핵심 CTA처럼 노출

## 처리 방식

### 등장인물/관계도
Map/작품 앱의 부가기능으로 유지 가능. SEO Work 본문에서는 제거.

### Quiz
페이지 최하단의 `재미로 더 보기` 정도로 축소. 핵심 navigation에서 제외.

### Guide
실제 여행 의도가 강한 검증된 Guide만 관련 링크 1개로 노출.

### 문화 콘텐츠
작품과 직접 관련성이 높은 1개 정도만 editorial link로 사용. 자동 다중 cross-link 지양.

# 6. Place Detail 새 구조

Place page는 장소 DB 카드가 아니라 **이 장소가 왜 작품 팬에게 의미가 있는지 증명하는 페이지**가 된다.

순서:

1. 장소명 + relationship badge
2. 이 작품에서 어떤 의미였나
3. Scene 1개 또는 대표 장면
4. `여기, 왜 가볼 만해?`
5. 현재 방문 시 알아야 할 정보 최대 3개
6. 지도/길찾기
7. 출처/검증 정보

## 피할 것
- 주변 장소 자동 나열 과다
- 관련 작품 자동 나열 과다
- 검증되지 않은 여행팁
- 행정정보를 채우기 위한 정보

---

# 7. Region / Person / Guide / Quiz 처리

## Region
지역별 콘텐츠가 실제 편집 가치가 있으면 유지.

단순히 장소 몇 개를 묶은 thin hub는:
- primary nav 제외
- sitemap/index 여부 audit
- 검색/사용 가치가 없으면 noindex 또는 통합 후보

**기존 검색유입 URL을 일괄 삭제하지 않는다.** GSC/색인 상태 확인 후 결정.

## Person
인물별 SEO 페이지 확대 중단.

인물은 작품 이해를 돕는 앱 내부 정보로 취급한다.

## Guide
사람이 선별한 3~5개 고품질 route만 유지/확장.
자동 대량생성 금지.

## Quiz
Retention/engagement 부가기능으로 유지.
검색 랜딩이나 core navigation 역할은 하지 않는다.

---

# 8. 다국어 정책

번역된 페이지 수보다 **언어별 완성도**를 우선한다.

페이지를 생성/색인하려면:
- title/meta 정상
- 핵심 본문 자연스러운 번역
- 장소명/관계 label 번역 일관
- 핵심 링크 동일 locale 유지
- 한국어 silent fallback 없음

미완성 locale은 섹션을 숨기거나 index 후보에서 제외한다.

---

# 9. 콘텐츠 Audit 등급

모든 Work/Place/Region 페이지를 다음 4등급으로 분류한다.

## A — KEEP / CORE
- 검색/사용 가치 있음
- 핵심 사실 검증 가능
- 대표 콘텐츠로 유지

## B — SIMPLIFY
- 가치 있음
- 정보량 과다/중복
- 핵심 3~5개만 남기고 구조 단순화

## C — RESEARCH BEFORE INDEX
- 장소 관계/근거가 약함
- 확인 후 공개 또는 noindex 후보

## D — MERGE / DE-EMPHASIZE
- 독립 페이지 가치 낮음
- 다른 Work/Place/Map 경험에 흡수

`페이지가 존재한다 = 계속 색인해야 한다`가 아니다.

# 10. Pilot 순서

전체 사이트를 한 번에 바꾸지 않는다.

## R1 — Work Detail Pilot 5개

1. `poksshak`
2. `breakingbad`
3. `byakuya`
4. `strangerthings`
5. `odyssey`

이유: Scene/Guide/Place 연결이 이미 준비되어 있어 구조조정 효과를 비교하기 쉽다.

### Pilot 합격 기준
- Hero부터 지도 CTA까지 한 눈에 이해
- 대표 장소 3~5개만 기본 노출
- 등장인물 리스트 기본 화면 제거
- 긴 전체 장소 목록 접힘/축소
- factual claim 수 감소
- 모든 노출 관계 정확
- mobile 360/390/430
- 기존 URL/canonical 유지

## R2 — Navigation / Homepage

Pilot 방향 승인 후 shared shell 단순화.

## R3 — 나머지 Work

콘텐츠 audit A/B 등급부터 순차 적용.

## R4 — Place / Region index hygiene

검색유입과 품질 데이터를 보고 noindex/merge 후보 확정.

# 11. 삭제하지 말아야 할 것

구조조정은 SEO 자산 파괴가 아니다.

기본 원칙:
- 기존 상위 Work URL 유지
- 기존 Place URL은 근거 없이 삭제하지 않음
- canonical/hreflang/x-default 보존
- sitemap 변경은 audit 후 별도 승인
- 301/404 대량 발생 금지

화면에서 숨기는 것과 URL 삭제를 구분한다.

# 12. Phase G와의 관계

Saved Places + My Map (#43)은 좋은 방향이지만, **현재 복잡한 정보구조 위에 기능을 추가하면 복잡도를 더 높일 수 있다.**

따라서 권장 순서:

```text
Current RC 안정화
→ Verified Minimalism R1 Pilot
→ navigation/home 단순화
→ Phase G 저장 기능
```

Phase G의 localStorage/storage schema 작업은 폐기하지 않는다. UI surface만 구조조정 이후의 새 IA에 맞춰 구현한다.

# 13. 최종 성공 기준

이 구조조정이 성공하면 사용자에게 그곳지금은 이렇게 느껴져야 한다.

> 작품을 선택하면
> 기억나는 장면 3개와
> 진짜 가볼 만한 장소 몇 곳을
> 믿을 수 있게 보여주는 서비스.

그리고 운영 측에서는:
- 페이지당 검증해야 할 claim 감소
- 콘텐츠 오류 발생면 감소
- 신규 작품 제작시간 감소
- 다국어 QA 범위 감소
- AdSense/검색 품질 대응이 쉬워짐

## North Star

**More content가 아니라 More trustworthy discovery.**
