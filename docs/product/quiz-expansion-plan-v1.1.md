# 그곳지금 퀴즈 확대 운영 기획안 v1.1

**SEO · 체류시간 · 장소 탐색을 함께 높이는 저공수형 퀴즈 운영안**  
작성일: 2026-08-25

## 핵심 결론

- 작품당 퀴즈를 10문제에서 20문제로 확대하고, 전체 작품에 같은 공통 컴포넌트로 일괄 적용한다.
- 로그인·랭킹·누적 포인트·공유 기능은 v1에서 제외한다.
- 배지는 저장형이 아니라 종료 화면에서만 보여주는 일회성 결과 배지로 운영한다.
- 정답/오답 뒤에는 관련 장소를 새 탭 또는 간단 오버레이로 열어 기존 퀴즈 상태를 유지한다.
- 작품별 독립 퀴즈 URL과 검색 가능한 질문·정답·짧은 해설 텍스트를 유지한다.

## 1. 기획 목표

- 작품 페이지에서 한 번 더 누르게 만드는 장치로 활용한다.
- 검색 유입 → 작품 글 → 퀴즈 → 장소 확인 → 퀴즈 복귀 → 지도/다른 장소의 이동 루프를 만든다.
- 공통 UI/로직은 한 번 구현하고 작품별 퀴즈 데이터만 공급한다.
- SEO 목적은 퀴즈 자체보다 작품별 추가 텍스트, 롱테일 키워드, 장소 내부링크 확대에 둔다.

## 2. 퀴즈 기본 운영안

| 항목 | v1 운영안 |
|---|---|
| 문항 수 | 작품당 20문제 |
| 출제 방식 | 1문제씩 표시, 4지선다 |
| 문항 순서 | 고정 또는 진입 시 랜덤 |
| 장소 연계 | 20문제 중 8~10문제 권장 |
| 진행 표시 | 문제 7/20 · 정답 5개 |
| 로그인 | 없음 |
| 점수 저장 | 기본 없음, 선택적으로 localStorage |
| 공유 | v1 제외 |
| 랭킹 | v1 제외 |

### 권장 문항 구성

| 유형 | 권장 수 | 예시 |
|---|---:|---|
| 작품 기억 | 5 | 인물, 사건, 대사 맥락 |
| 장소·촬영지 | 8 | 실제 촬영지, 배경지, 세트 위치 |
| 숨은 이야기·비하인드 | 4 | 촬영 비하인드, 제작 설정, 반전 정보 |
| 팬 문제 | 3 | 세부 설정, 장소와 장면 연결 |

## 3. 사용자 흐름

1. 작품/지도 페이지에서 “나 이 작품 얼마나 알까?” 클릭
2. 퀴즈 모달에서 1/20 시작
3. 답 선택 → 즉시 정답/오답 + 짧은 해설
4. 장소 문제면 “이 장소 보기” 노출
5. 새 탭 또는 간단 오버레이로 장소 확인
6. 원래 퀴즈로 돌아와 다음 문제
7. 20문제 완료 → 점수 + 일회성 결과 배지 + 관련 장소/다른 작품 CTA

## 4. 정답·오답 피드백

### 정답 예시

- 일반: “맞았어. 이건 기억하고 있었네.”
- 장소: “맞았어. 바로 그곳이야. 실제 장소는 지금도 찾아갈 수 있어.”
- 반전: “맞았어. 화면은 제주였는데 실제 촬영은 고창. 알고 보면 장면이 좀 다르게 보여.”
- 팬 문제: “이걸 맞힌다고? 꽤 제대로 봤는데.”

### 오답 예시

- “아, 이건 살짝 헷갈릴 만했어. 정답은 {정답}.”
- “거의 갔는데 한 칸 옆이었네. 정답은 {정답}.”
- “이건 제작진이 좀 속였어. 실제로는 {정답}.”
- “화면만 보면 그렇게 보이는데, 진짜 장소는 {정답}.”
- “여기서 한 번 미끄러졌네. 다음 문제에서 만회하면 됨.”
- “나도 처음엔 그건 줄 알았어. 근데 정답은 {정답}.”

## 5. 정답 후 장소 연결

가장 저공수인 방식은 장소를 새 탭으로 여는 것이다.

- 퀴즈 상태가 원래 탭에 남아 별도 상태복원 로직이 거의 필요 없다.
- 장소 페이지/지도에서 위치·사진·가는 법을 확인한 뒤 원래 탭에서 진행한다.
- 모바일 UX가 불편하면 기존 장소 상세 오버레이 재사용을 2순위로 검토한다.

## 6. UI 제안

### 진행 화면

```text
🎬 폭싹 속았수다 퀴즈
문제 7 / 20 · 정답 5개

Q. 애순과 관식의 유채꽃 장면은 실제 어디에서 촬영됐을까?
[ 제주 성산 ]
[ 전북 고창 ]
[ 부산 기장 ]
[ 경북 안동 ]
```

### 답 선택 후

```text
✅ 맞았어. 바로 그곳이야.
실제 촬영지는 전북 고창 학원농장.
제주처럼 보이지만 실제 장소는 달랐어.

[📍 이 장소 보기 ↗] [다음 문제 →]
```

### 완료 화면

```text
20문제 완료
16 / 20
🌊 꽤 제대로 본 사람

[이 작품 장소 보러가기]
[다른 작품 퀴즈 풀기]
```

## 7. 배지 운영

v1에서는 수집형 배지를 만들지 않는다.

| 정답 수 | 표시 예시 |
|---:|---|
| 0~7 | 이제 막 들어온 사람 |
| 8~13 | 꽤 본 사람 |
| 14~18 | 찐팬 인정 |
| 19~20 | 이 작품 마스터 |

작품별 명칭은 바꿀 수 있지만 개발상으로는 4개 점수 구간만 공통 사용한다. 원하면 localStorage로 작품별 최고점만 저장할 수 있다.

## 8. SEO 설계

- 작품별 URL 예: `/works/squidgame/quiz/`
- title 예: `오징어게임 퀴즈 20문제 | 촬영지와 숨은 이야기까지 얼마나 알고 있을까?`
- JS 모달만 두지 않고 검색엔진이 읽는 소개·질문·정답 해설 텍스트를 HTML에 포함한다.
- 장소 문제 해설에 장소 페이지/지도 내부링크를 연결한다.
- 목표는 퀴즈 리치결과보다 `작품명+퀴즈`, `작품명+촬영지`, `장소명+작품명` 롱테일 확대다.

## 9. 전체 콘텐츠 일괄 적용

시범 5개가 아니라 전체 작품 일괄 적용을 권장한다. UI/로직은 동일하고 작품별 차이는 데이터뿐이다.

현재 39개 작품 기준 총 780문제. 개발자가 퀴즈를 직접 작성한다면 운영 측 부담은 장소 링크와 공통 문구 검수 정도로 제한한다.

## 10. 개발 최소화 구현안

| 항목 | 권장 방식 |
|---|---|
| 컴포넌트 | `QuizModal` 1개 공통 |
| 데이터 | work별 JSON/DB: question, options, answer, explanation, place_url(optional) |
| 진행 상태 | 모달 내부 state |
| 장소 보기 | `target=_blank` 권장 |
| 최고점 | 선택적으로 localStorage |
| 배지 | 점수 구간별 텍스트/아이콘 |
| 로그인 | 미도입 |
| 랭킹 | 미도입 |
| 공유 이미지 | 미도입 |
| SEO | 작품별 `/quiz/` 정적 URL + indexable intro/해설 |

## 11. 출시 후 최소 지표

- `quiz_start`
- `quiz_complete`
- `quiz_place_click`
- `quiz_next_work`
- Search Console의 `작품명 + 퀴즈` 관련 노출·클릭

GA4도 위 4개 이벤트부터 넣고 문항별 세부 통계는 사용자 규모가 커진 뒤 추가한다.

## 12. 최종 개발 우선순위

1. 전체 작품 20문제 데이터 확보
2. 공통 퀴즈 UI 20문제 기준 확장
3. 정답/오답 피드백 + 장소 보기
4. 장소 새 탭 열기와 퀴즈 상태 유지
