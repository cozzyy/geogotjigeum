# 공공데이터 API 연동 — 장소 카드 실시간/실용 정보 위젯 v1 (파일럿: 케이팝 데몬헌터스)

작성: Claude (Cowork) / 작성일: 2026-09-21
상태: Planning (승인 대기)

## 목적

그곳지금의 장소 카드(`site/contentmap_*_locations.js` → 작품 상세/장소 상세 페이지)는 현재 수작업으로 조사한 정적 정보(주소, 설명, travelTip 등)로 채워져 있다. 공공데이터포털(data.go.kr) 및 서울 열린데이터광장의 공개 API를 연동해 (1) 주소·운영시간 등 실용정보를 자동으로 최신화하고, (2) 사이트 컨셉인 "그곳, 지금"에 맞는 실시간성 정보(혼잡도, 날씨)를 장소 카드에 추가하는 것을 목표로 한다.

이번 문서는 **케이팝 데몬헌터스(kdemonhunters)** 12개 장소를 파일럿으로 삼아 범위를 좁혀 제안한다. 검증되면 다른 작품의 장소 카드에도 같은 파이프라인을 재사용할 수 있다.

## 배경 / 출처

- 사용자(인형님)와의 기획 논의: 공공데이터포털 API를 활용한 서비스를 만들고 싶고, 그곳지금 콘텐츠와 매칭되면 좋겠다는 방향 확인.
- `site/contentmap_kdemonhunters_locations.js` 실사 확인: 12개 장소 모두 서울 소재, 좌표(lat/lng)·설명·태그·travelTip 필드로 구성된 순수 JS 배열.
- 조사한 후보 API(가장 관련 높은 순):
  - 한국관광공사 국문 관광정보 서비스_GW(TourAPI) — https://www.data.go.kr/data/15101578/openapi.do — 주소·운영시간·홈페이지·전화번호·대표이미지 등 실용 정보.
  - 서울 열린데이터광장 실시간 도시데이터 — https://data.seoul.go.kr/SeoulRtd/ — 고궁·문화유산/공원/관광특구/발달상권/인구밀집지역 등 약 50개 핫스팟의 실시간 혼잡도. data.go.kr 범위 밖(서울시 자체 포털), 별도 신청 필요.
  - 기상청 단기예보 API — 좌표 기반 "지금 날씨".
  - 궁능유적본부(국가유산청) — 경복궁 등 고궁 관람시간/휴궁일 정보. data.go.kr 등록 여부 별도 확인 필요.

## 개발 범위

- kdemonhunters 12개 장소에 한해 TourAPI로 주소·운영정보를 조회해보고 데이터 품질(정확도/최신성)을 검증한다.
- 검증되면 장소 카드에 "실시간 혼잡도"와 "지금 날씨" 위젯을 추가하는 프로토타입을 만든다 (우선 kdemonhunters 페이지 한정, 다른 작품엔 적용하지 않음).
- 위 두 항목은 기존 `description`/`tag`/`travelTip` 필드는 건드리지 않고, 새 필드(예: `liveInfo`)를 추가하는 방식으로 최소 침습적으로 붙인다.

## 제외 범위

- 12개 장소 외 다른 작품 확장은 이번 파일럿에서 하지 않는다.
- 영화·드라마 촬영지 자체를 공공API로 자동 발굴하는 것은 이번 범위가 아니다 (공공API에 촬영지 데이터가 없음을 조사로 확인함).
- 유료 API/유료 티어 전환은 이번 파일럿 범위가 아니다 (무료 티어로 검증 가능한 범위까지만).
- 실제 배포(main 반영)는 이번 파일럿의 로컬/브랜치 검증까지만 포함하고 별도 승인 없이 진행하지 않는다.

## Claude 검토 요청

1. 구현 가능 여부: TourAPI, 서울 열린데이터광장 모두 무료 오픈API이며 인증키 발급만으로 조회 가능 — 구현 가능.
2. 기존 코드/기능과 충돌 여부: 기존 `contentmap_kdemonhunters_locations.js` 필드는 유지하고 신규 필드만 추가하므로 충돌 낮음. 다만 `site/generate_place_pages.js`, `site/generate_work_pages.js` 등 생성기가 이 데이터 구조를 어떻게 읽는지는 코드 확인이 더 필요함.
3. 권장 구현 방법과 변경 영역: 1) API 키 발급(사용자 계정으로, Secret은 저장소에 커밋하지 않음) → 2) 별도 조회/캐싱 스크립트로 응답 샘플 확보(빌드타임 또는 별도 백엔드 필요 여부 검토) → 3) 검증되면 `contentmap_kdemonhunters_locations.js`에 필드 추가 + 관련 생성기/템플릿 수정.
4. 사용자 결정이 필요한 항목:
   - 실시간 데이터를 빌드타임에 정적으로 굽을지, 클라이언트에서 매번 API를 호출할지 (후자는 API 키 노출/쿼터 문제 고려 필요).
   - 서울 열린데이터광장처럼 data.go.kr 범위 밖의 별도 포털 API도 함께 쓸지.
   - 이번 파일럿을 kdemonhunters 하나로 한정할지, 처음부터 여러 작품을 함께 검증할지.
5. 테스트 계획: API 응답 샘플을 수집해 실제 장소 12곳과 대조, 모바일 360/390/430px에서 위젯 레이아웃 확인, 기존 페이지 로드 성능 영향 확인.
