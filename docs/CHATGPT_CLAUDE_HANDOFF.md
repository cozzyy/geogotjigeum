# CHATGPT → CLAUDE HANDOFF — 기획에서 개발로 넘기는 표준 절차

## 1. 목적
ChatGPT는 기획자, Claude는 개발자를 기본 역할로 한다. 둘은 서로의 대화 기억에 의존하지 않고 GitHub의 문서·Issue·PR을 통해 업무를 인수인계한다.

핵심 흐름:

`사용자 아이디어 → ChatGPT 기획 → GitHub 기획문서 + Handoff Issue → Claude 기술검토 → 사용자 승인 → Claude 개발/테스트 → PR → Review → Done`

## 2. ChatGPT가 기획을 끝냈을 때 해야 할 일
1. 기획안을 적절한 위치에 Markdown으로 저장한다.
   - 기능/UX: `docs/product/`
   - 콘텐츠: `docs/content/`
   - SEO: `docs/seo/`
   - QA: `docs/qa/`
2. 기존 코드·문서·Issue와 중복 여부를 확인한다.
3. 개발이 필요한 경우 `기획 → 개발 인수인계` Issue를 만든다.
4. Issue에 반드시 기획문서 경로, 목적, 범위, 제외범위, 완료기준, 사용자 결정이 필요한 항목을 적는다.
5. 개발 전 상태는 기본적으로 `Dev Review`로 본다. ChatGPT가 임의로 `Approved`로 간주하지 않는다.

## 3. Claude가 Handoff Issue를 받았을 때
Claude는 코드를 바로 수정하지 않는다. 먼저 다음을 읽는다.

1. `AGENTS.md`
2. `CLAUDE.md`
3. `docs/PROJECT_STATE.md`
4. Handoff Issue
5. 연결된 기획문서
6. 관련 코드와 최근 PR

그 다음 기술 검토 결과를 Issue에 남긴다.

### A. READY FOR APPROVAL
- 구현 가능
- 기존 구조와 큰 충돌 없음
- 사용자 판단이 필요한 핵심 쟁점 없음
- 권장 구현방법과 예상 변경영역 제시
- **아직 개발은 시작하지 않음**

### B. NEEDS DECISION
- 사용자 결정 없이는 구현방향이 갈릴 수 있음
- Claude는 질문을 1~3개로 줄인다.
- 각 질문은 가능한 경우 `A / B / 추천안 / 이유` 형식으로 작성한다.
- 답변 전까지 해당 개발을 중단한다.

### C. BLOCKED
- 코드, 환경, 권한, 외부 의존성 등으로 검토 또는 개발이 불가능함
- 무엇이 부족한지와 필요한 다음 행동을 명확히 적는다.

## 4. 사용자 승인 규칙
수동 운영 단계에서는 다음 중 하나가 명확히 기록되어야 개발을 시작할 수 있다.

- Issue 댓글에 `개발 승인`
- Issue 댓글에 `APPROVED`
- ChatGPT가 사용자의 명시적 승인을 받은 뒤 Issue에 승인 사실을 기록

`좋아`, `진행해`, `괜찮네`처럼 맥락상 애매할 수 있는 표현은 중요한 개발에서 승인으로 추정하지 않는다.

## 5. Claude 개발 단계
승인 후 Claude는 다음 순서로 진행한다.

1. Issue 번호와 연결된 branch 생성
2. 구현
3. 테스트/QA
4. PR 생성
5. PR에 다음을 기록
   - 무엇을 바꿨는지
   - 테스트 결과
   - 기획안과 달라진 점
   - 남은 위험/후속작업
6. 관련 Issue와 PR 연결
7. Merge 전 사용자 또는 지정 Reviewer 검토

## 6. Claude가 임의로 결정해도 되는 범위
다음은 기획 의도를 바꾸지 않는 한 개발자가 합리적으로 판단할 수 있다.
- 변수명/함수명
- 내부 파일 분리
- 동등한 구현 방식 중 단순한 선택
- 코드 포맷팅
- 테스트 구조
- 명백한 버그 수정

다음은 사용자의 결정 없이 바꾸지 않는다.
- 화면/사용자 흐름의 핵심 변경
- 기획 기능 삭제 또는 추가
- 유료 API/서비스 도입
- 개인정보/회원가입/결제 관련 구조
- 데이터 모델의 큰 변경
- 기존 URL/SEO 구조의 대규모 변경
- 운영 배포 방식의 큰 변경
- 예상 유지비가 늘어나는 선택

## 7. Handoff Issue 최소 형식

```text
[HANDOFF] 작업명 - Claude 개발 검토

기획문서:
docs/.../plan.md

목적:
왜 필요한가

개발 범위:
- ...

제외 범위:
- ...

완료 기준:
- [ ] ...

Claude 검토 요청:
1. 구현 가능 여부
2. 기존 코드와 충돌 여부
3. 권장 구현방법
4. 사용자 결정 필요 항목
5. 테스트 계획

개발 승인 상태:
NOT APPROVED
```

## 8. 사용자가 GitHub를 직접 보지 않아도 되는 운영
사용자가 ChatGPT에서 `현재 Claude가 물어본 것 있어?`, `승인 필요한 거 보여줘`, `이거 개발 승인`이라고 말하면 ChatGPT가 GitHub의 Issue/PR을 확인하고 요약·기록할 수 있다.

즉 사용자는 GitHub UI를 매번 직접 다룰 필요가 없다. GitHub는 기록과 상태의 중심이고, ChatGPT는 대표에게 보여주는 기획·의사결정 인터페이스 역할을 한다.

## 9. 자동화는 나중에
초기에는 수동으로 2~3건을 운영해 질문 기준과 승인 기준을 안정화한다. 이후 필요할 때 Claude GitHub 연동, GitHub Actions, 알림 자동화를 추가한다.

자동화보다 먼저 이 프로토콜이 실제 작업에서 잘 작동하는지 검증한다.
