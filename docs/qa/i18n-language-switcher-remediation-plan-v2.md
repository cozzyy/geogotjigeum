# 다국어 페이지 일관성 개선안 v2 — 언어 전환·번역 준비상태 통합

작성일: 2026-08-26  
상태: 개발 착수 전 승인용 수정안  
기준: `site/` 실제 소스 및 `qa/language-toggle-audit-2026-08-25.md`

## 1. 결론

기존 점검 문서는 “후킹페이지마다 KR / EN / JP / 中文 노출이 다르다”는 현상을 정확히 발견했다. 다만 현재 소스를 대조한 결과, 해결 목표를 **모든 페이지에 4개 버튼을 무조건 표시하는 것**으로 잡으면 안 된다.

정확한 목표는 아래다.

> 한 콘텐츠의 언어별 실제 준비상태를 한 곳에서 관리하고, 지도 앱·작품 페이지·장소 페이지·지역 페이지가 그 규칙을 공유한다. 번역이 없는 언어를 해당 언어인 것처럼 보여 주거나 다른 언어로 조용히 보내지 않는다.

현재 중국어 구현은 간체가 아니라 **번체 중국어(`zh-Hant`, 대만·홍콩 대상)** 이다. 이번 작업에서는 기존 URL `/zh/`와 `zh-Hant`를 유지한다. 간체 중국어(`zh-Hans`) 추가는 별도 제품·콘텐츠 결정으로 분리한다.

## 2. 실제 소스 대조 결과

| 영역 | 현재 구현 | 문제/위험 |
|---|---|---|
| 지도 SPA | `contentmap_app.js`가 KR/EN/JP/中文 버튼을 항상 표시하고 `setLang()`으로 URL을 바꾼다. 작품 상세 링크는 JP/ZH 번역이 없으면 영어 작품 페이지로 보낸다. | 사용자가 JP/中文을 선택했는데 작품 상세에서 영어로 바뀔 수 있다. |
| 작품 정적 페이지 | `generate_work_pages.js`는 `title_ja` / `title_zh`가 있는 작품만 JP/ZH 파일·버튼을 만든다. `hreflang`도 실제 파일이 있는 언어만 넣는다. | SEO 규칙은 대체로 맞지만, 앱과 동작 정책이 다르다. 생성기 내부에만 준비상태 규칙이 있다. |
| 장소 정적 페이지 | `generate_place_pages.js`는 JP/ZH 장소 파일을 제한적으로 생성하고 `hreflang`도 제한한다. | 페이지 헤더에는 공통 언어 스위처가 없다. 장소의 언어 전환 경험이 작품·지역 페이지와 다르다. |
| 지역 정적 페이지 | `generate_region_pages.js`는 4개 언어 링크와 4개 지역 페이지를 항상 생성한다. | 작품 카드·제목의 누락 필드는 EN 또는 KO로 폴백할 수 있어 “해당 언어 페이지” 안에 다른 언어가 섞일 수 있다. |
| 콘텐츠 데이터 | 각 생성기에 `title_ja`, `title_zh` 존재 여부를 직접 검사하는 코드가 중복돼 있다. | 새 콘텐츠/새 페이지 유형이 생길 때 규칙 누락과 표시 불일치가 재발한다. |

### 유지해야 할 좋은 점

- 번역 파일이 없는 URL을 `hreflang`에 넣지 않는 현재 작품·장소 생성기의 SEO 원칙은 유지한다.
- 404를 피하려는 의도도 유지한다. 단, 언어 선택 UI가 영어 페이지로 조용히 이동하는 방식은 바꾼다.
- 기존 한국어·영어 URL, `/ja/`, `/zh/` URL은 변경하지 않는다.

## 3. 제품/UX 계약

### 공통 언어 목록과 표기

- 내부 코드: `ko`, `en`, `ja`, `zh-Hant`
- URL: `/`, `/en/`, `/ja/`, `/zh/`
- 화면 표기: `한국어 / English / 日本語 / 繁中`
  - 좁은 화면은 `KR / EN / JP / 繁中` 허용
  - 기존 `中文`은 번체인지 불명확하므로 `繁中`으로 바꾼다.

### 언어 버튼 규칙

1. 모든 페이지 유형(지도 앱·작품·장소·지역·향후 콘텐츠 페이지)은 같은 순서의 스위처를 가진다.
2. 번역본이 실제로 존재하면 그 **동일 엔티티의 동일 언어 URL**로 이동한다.
3. 번역본이 없으면 버튼은 숨기지 말고 `준비 중` 상태로 표시한다. 링크가 아니며 현재 페이지를 떠나지 않는다.
4. JP/繁中 버튼을 누른 결과로 영어나 한국어 페이지에 조용히 도착해서는 안 된다.
5. 현재 언어는 텍스트뿐 아니라 `aria-current="page"`와 동일한 활성 스타일로 표시한다.
6. 한 페이지 안의 제목·요약·장소명·CTA가 다른 언어로 폴백되지 않도록 한다. 불가피한 고유명사는 원문 유지 가능하지만, 정책을 데이터에 명시한다.

## 4. 기술 설계

### 4.1 단일 준비상태 레지스트리

`site/i18n/locale-availability.js` 또는 JSON 파일을 추가한다. 각 엔티티와 언어의 상태를 한 곳에서 선언한다.

```js
{
  entityType: 'work',
  id: 'pachinko',
  locales: {
    ko: { status: 'published', url: '/works/pachinko/' },
    en: { status: 'published', url: '/en/works/pachinko/' },
    ja: { status: 'published', url: '/ja/works/pachinko/' },
    'zh-Hant': { status: 'planned' }
  }
}
```

상태는 최소 `published` / `planned` / `hidden`으로 제한한다. `published`는 페이지 파일, 필수 텍스트, 메타, 테스트가 모두 존재할 때만 가능하다.

### 4.2 공통 헬퍼

바닐라 JS 구조는 유지하며 다음 공통 함수를 만든다.

- `getLocaleStatus(entityType, id, locale)`
- `getLocalizedUrl(entityType, id, locale)`
- `renderLanguageSwitcher({ entityType, id, currentLocale })`
- `buildHreflangLinks({ entityType, id })`

각 생성기와 `contentmap_app.js`는 직접 `title_ja` / `title_zh`를 검사하거나 영어 URL로 폴백하지 않고 이 헬퍼만 사용한다.

### 4.3 생성·데이터 규칙

- 작품이 `published`가 되려면 제목, SEO title/description, 요약, UI 문구, 노출되는 장소명/설명 데이터의 해당 언어 준비상태를 검증한다.
- 장소는 부모 작품의 언어 상태만 복사하지 않는다. 장소별 필수 필드가 갖춰졌을 때만 `published`다.
- 지역 페이지는 지역명·소개·연결 작품 카드가 해당 언어 준비상태일 때만 `published`다.
- 생성 스크립트는 레지스트리와 실제 출력 파일의 불일치를 오류로 종료한다.
- 새 콘텐츠 추가 시 레지스트리 항목이 없으면 빌드가 실패해야 한다.

### 4.4 SEO 규칙

- canonical은 현재 페이지의 실제 URL이다.
- `hreflang`은 `published` 언어만 출력한다.
- `zh-Hant`을 유지한다. `zh-Hans`를 넣지 않는다.
- sitemap에는 실제 생성된 `published` URL만 넣는다.
- `x-default`는 한국어 URL을 유지한다.

## 5. 구현 순서

### P0 — 동작 일관성 회복

1. 공통 locale 정의·준비상태 레지스트리·스위처 헬퍼를 만든다.
2. `contentmap_app.js`의 `workHubPath()` 영어 조용한 폴백을 제거한다.
3. `generate_work_pages.js`, `generate_place_pages.js`, `generate_region_pages.js`를 공통 헬퍼로 전환한다.
4. 장소 페이지 헤더에도 공통 스위처를 추가한다.
5. `中文` 라벨을 `繁中`으로 통일한다.

### P1 — 데이터/출력 정합성

1. 기존 41개 작품과 해당 장소·지역을 레지스트리로 이관한다.
2. `published`인 페이지의 필수 번역 필드를 검사한다.
3. 누락 번역은 `planned`로 표시하고 화면에서 ‘준비 중’ 처리를 확인한다.
4. 정적 페이지·sitemap을 재생성한다.

### P2 — 자동 검증과 배포 게이트

Node 기반 검사 또는 Playwright를 추가하고 CI에서 실행한다.

- 모든 페이지 유형의 스위처 순서·라벨·활성 상태
- `published` 버튼 URL 200 및 동일 entity ID 확인
- `planned` 버튼은 링크가 아니고 ‘준비 중’ 표시
- 활성 언어와 `<html lang>`, canonical, `aria-current` 일치
- `published` 언어만 hreflang/sitemap에 존재
- 신규 콘텐츠에 레지스트리 항목이 없거나 필수 필드가 빠지면 실패

## 6. 완료 판정

- 지도·작품·장소·지역 페이지에서 KR → EN → JP → 繁中 순서가 동일하다.
- 실제 번역이 있는 버튼은 같은 콘텐츠의 해당 언어 페이지로 이동한다.
- 번역이 없는 버튼은 다른 언어로 이동하지 않고 ‘준비 중’으로 명확히 보인다.
- 같은 언어 페이지 안에 번역 누락으로 인한 임의 KO/EN 문단이 남지 않는다.
- 자동 검증이 통과하고, 생성 후 변경된 정적 파일·sitemap이 커밋에 포함된다.
- 배포 전 PR에서 대표 확인 항목(표본 1개씩: 완비/JP 미완료/繁中 미완료)이 기록된다.
